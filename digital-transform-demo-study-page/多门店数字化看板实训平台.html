项目背景与业务痛点

Business Background
数据孤岛各门店独立收银/会员系统，数据互不相通，无法横向对比
口径不一门店间字段、单位、命名混乱，总部难以统一统计
报表滞后人工汇总 Excel，日报延迟且易出错，缺乏实时洞察
无法决策缺乏统一指标库，管理层无法看到全盘经营全局
成本高企每个门店一套系统，重复建设、运维成本高
无数据资产历史数据散落，难以沉淀为可复用的数据资产
核心思路
通过「采集各门店业务库数据 → 统一进入 HDFS → 按 ODS/DWD/DWS 分层建模 → PySpark 清洗与聚合 → 落库 MySQL 指标库 → Flask + ECharts 输出可视化看板」，把散落的数据孤岛汇聚成企业级统一指标视图。

环境使用注意事项（必修）

Critical Notes
禁止给虚拟机做快照
快照会大量占用 E 盘存储空间，导致磁盘爆满。如需回退请谨慎评估，不要随手打快照。
HDFS 只能格式化一次
hdfs namenode -format 仅在首次启动前执行一次，多次格式化会丢失全部数据。
PySpark 环境变量
Windows 驱动与虚拟机 worker 需 Python 版本一致（均 3.8）。连接虚拟机时显式指定：spark.pyspark.python=/opt/miniconda3/bin/python，不要在 Windows 上把 PYSPARK_PYTHON 设成 Linux 路径。
不修改系统 JAVA_HOME
IDEA 自带 Java17，保护它；PySpark 请用 PYSPARK_JAVA_HOME=D:\jdk1.8。
不升级 / 不卸载
不要升级现有 Anaconda base、不要卸载已装软件，保持版本锁定：Hadoop3.1.3 + Spark3.1.2 + Scala2.12.10 + JDK1.8。
防火墙规则
Windows 高级防火墙已放行 Spark-Driver-Ports（入站 TCP 40000-60000），供 Spark executor 回连 driver。不要全盘关闭防火墙。
内存规划
虚拟机固定 4G 内存，跑大数据组件时尽量关闭 Windows 多余软件，避免内存不足卡顿或虚拟机闪退。

正确答案：B

3.1 MySQL 业务库建表 + 模拟数据生成

3.2 Python 抽取 MySQL 数据上传 HDFS

Ingest to HDFS

把各门店 MySQL 的数据抽出来，统一写入虚拟机的 HDFS 原始目录，作为数仓的数据源。采集是「消除数据孤岛」的第一步——把散落数据汇聚到一处。

采集链路

MySQL (shop_a/shop_b) → Python 读取 → 转为统一 CSV → 上传到 HDFS /data/ods/sales/

collect_to_hdfs.py · 采集上传
知识点
HDFS 是分布式文件系统，适合一次写入、多次读取的大数据。采集环节的关键是统一格式（统一 CSV 表头），把不同门店的口径拉齐，为后续数仓分层打基础。

3.3 Hive 数仓分层：ODS / DWD / DWS 建表

Data Warehouse Layering

数仓采用经典的分层建模思想。Hive 3.1.2 中，用 HiveQL 建立各层表，把 HDFS 上的原始数据组织成可分析的结构。

三层含义

层名称职责
ODS贴源层与源数据保持一致，原样接入，不加工（落地原始 CSV）
DWD明细层清洗、去重、标准化，形成统一口径的明细事实表
DWS汇总层按门店/商品/日期等维度预聚合，形成宽表，供指标查询
hive_ods_dwd.sql · ODS / DWD 建表
hive_dws.sql · DWS 汇总层
知识点
ODS「原样接」、DWD「清洗标准化」、DWS「预聚合」——分层让数据可回溯、可复用、性能可控，避免大量即席计算重复跑。

核心概念题库

数仓 · 数据孤岛 · 数字化转型

覆盖面试高频考点，含单选与简答，均附参考答案。先自测，再看答案。

单选题
简答题
单选什么是「数据孤岛」？
正确答案：B
数据孤岛指数据分散在不同系统，无法统一访问与整合，导致难以做全局分析。
单选数仓分层中，ODS 层的主要作用是？
正确答案：B
ODS（贴源层）原样接入源数据，保留原始性，便于回溯与排查。
单选事实表与维度表的区别是？
正确答案：A
事实表存度量值（金额、数量）并可聚合；维度表存描述性字段（门店名、分类），用于分组筛选。
单选HDFS 中「一次写入、多次读取」最适合哪种数据？
正确答案：B
HDFS 适合大批量、顺序追加、读多写少的场景，不适合高频随机更新。
单选企业数字化转型的核心目标通常是？
正确答案：B
数字化转型本质是用数据和技术优化决策、流程与体验，而不只是「线上化」。
单选DWS 汇总层相比 DWD 明细层的优势是？
正确答案：B
DWS 把常用指标预先算好，看板等查询直接读，避免重复全量计算，性能更好。
简答请简述多门店销售「数据孤岛」问题及其治理思路。
参考答案
痛点：各门店系统独立、数据格式口径不一、无法统一分析，导致管理难、决策滞后。
治理思路：① 统一采集各门店数据到 HDFS；② 通过数仓分层（ODS/DWD/DWS）标准化建模；③ 用 PySpark 清洗、聚合出统一指标；④ 指标落库 MySQL；⑤ 用可视化看板统一呈现，实现数据驱动决策。
简答为什么数仓要分层？ODS、DWD、DWS 各解决什么问题？
参考答案
分层为了解耦、可复用、易回溯、控成本。
ODS 原样接入，保留原始数据便于排查；DWD 统一口径、清洗标准化，形成一致明细；DWS 预聚合宽表，支撑高效查询与指标复用。分层让不同需求各取所需，避免重复加工。
简答PySpark 在 Windows 驱动连接远程集群时可能遇到什么问题？如何解决？
参考答案
常见问题：① worker 与 driver 的 Python 版本不一致报错 —— 通过 spark.pyspark.python 和 spark.executorEnv.PYSPARK_PYTHON 统一指定集群侧 Python；② executor 无法回连 driver —— 在 Windows 防火墙放行 driver 随机端口区间（如 40000-60000）；③ 依赖 winutils 警告 —— 通常不影响运行，可忽略。
简答从「多门店 MySQL」到「可视化看板」，描述一条完整的数据流转链路。
参考答案
各门店 MySQL 业务库 → Python(PyMySQL) 抽取 → 上传 HDFS 原始目录 → Hive 建 ODS 贴源表 → PySpark 清洗得 DWD 明细 → PySpark 聚合得 DWS 汇总 → 指标落库到 MySQL 指标库 → Flask 提供查询接口 → 前端 ECharts 渲染看板。整条链路实现从业务数据到经营洞察。

踩坑手册

常见报错与解决方案

把实操中最容易踩的坑提前列出来，遇到报错先来这里对号入座。

报错：Python in worker has different version 3.6 than that in driver 3.8
原因：Windows driver 与虚拟机 worker 的 Python 版本不一致。
解决：在 SparkSession 中显式添加 spark.pyspark.python=/opt/miniconda3/bin/python 与 spark.executorEnv.PYSPARK_PYTHON=/opt/miniconda3/bin/python，并确保 worker 的 PYSPARK_PYTHON 也指向该路径。
报错：Task 0 in stage 0.0 failed ... 作业挂起/卡死
原因：executor 无法回连 Windows 的 driver（防火墙拦截）。
解决：Windows 高级防火墙放行入站 TCP 40000-60000（Spark driver 随机端口区间），规则名可设为 Spark-Driver-Ports，不要关闭整个防火墙。
报错：Name or service not known / Connection refused (HDFS 9870 打不开)
原因：虚拟机 Hadoop 服务未启动，或主机名/IP 映射缺失。
解决：在虚拟机执行 start-dfs.sh、start-yarn.sh；确保 /etc/hosts 有 192.168.112.128 hadoop 映射；Windows 访问用 http://192.168.112.128:9870。
报错：Permission denied (HDFS 写入失败)
原因：HDFS 目录权限不足或用户不对。
解决：用 hdfs dfs -mkdir -p /data/ods/sales 建目录并 hdfs dfs -chmod 777 /data/ods/sales，或使用 root 用户执行。
报错：Spark 作业报 MRAppMaster 找不到主类
原因：Hive 3.1.2 与 Hadoop 3 的 jar 遮蔽冲突。
解决：在 Hadoop 的 mapred-site.xml 中把 mapreduce.application.classpath 配成绝对路径（Hadoop3 的 jar 目录），并调小 YARN/MapReduce 内存参数避免超出虚拟机 4G。
报错：Cannot connect to MySQL server (Hive 连元数据库失败)
原因：Hive 连接 MySQL 元数据库配置有误或未授权。
解决：检查 hive-site.xml 的 JDBC URL、账号；给 Hive 用户授权 GRANT ALL ON hive.* TO 'hive'@'%'；确认 MySQL 开启远程访问。
警告：Did not find winutils.exe (Windows PySpark)
原因：Windows 上 Hadoop 需要 winutils，未配置。
解决：该警告通常不影响运行，可忽略；若影响则把 hadoop.dll/winutils 放入 Hadoop bin 目录。
风险：给虚拟机打快照导致磁盘爆满
原因：快照占用大量 E 盘空间。
解决：禁止随意快照；若已打，及时删除多余快照，保证 E 盘余量。
